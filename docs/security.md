# 安全模型

laoHuangCode 是学习原型，不是完整沙箱。权限确认降低误操作概率，但不能把不可信
模型输出变成安全代码。

## 默认权限

| 工具 | 默认行为 | 原因 |
| --- | --- | --- |
| `read` | 自动允许 | 仅允许读取项目根目录内的 UTF-8 文件 |
| `write` | 每次确认 | 会创建或完整覆盖文件 |
| `edit` | 每次确认 | 会修改现有文件 |
| `bash` | 每次确认 | 可执行任意 Bash 命令 |

确认时，文件正文和替换文本只显示字符数，不把完整内容重复打印到终端。输入 `a` 的
放行只对当前进程有效。`--dangerously-skip-permissions` 会关闭全部写操作确认，适合
一次性容器等已隔离环境，不建议日常使用。

## 已有防护

- `read`、`write`、`edit` 将解析后的路径限制在启动目录内。
- 文件工具阻止 `..` 和符号链接越过项目根目录。
- `edit` 只接受恰好出现一次的旧文本，避免模糊批量替换。
- Web 面板只监听 `127.0.0.1`，事件仅驻留内存。
- 工具日志隐藏 `content`、`old_text`、`new_text` 的正文。
- Bash 子进程移除 `OPENAI_API_KEY`、`DEEPSEEK_API_KEY` 和
  `LAOHUANG_API_KEY`。

## 明确不保证的边界

- Bash 没有文件系统、网络、进程或系统调用沙箱。
- Bash 可以读取其他环境变量和用户可访问的文件。
- 项目内文件可能包含提示注入内容，诱导模型请求危险工具。
- 权限确认展示的是参数摘要，用户仍需理解命令含义。
- 目前没有命令 allowlist、Git 回滚、资源配额或审计持久化。

因此应在版本控制下的项目中运行，提交或暂存重要改动，并避免在包含生产密钥的宿主
环境中使用危险跳过参数。
