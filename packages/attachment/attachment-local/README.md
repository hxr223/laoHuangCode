# @laohuang/attachment-local

本地 `AttachmentStore` 实现：流式内容寻址存储、Sharp 图片处理、SQLite 跨进程协调。
CLI 共享根为用户主目录下 `.laohuang/attachments`，不放在项目目录中。

```text
attachments/
  metadata.sqlite           生命周期、活跃操作、上次成功清理时间
  objects/<前两位>/<sha256>   原始字节，不修改原图
  variants/<sha256>/*.json   可重建请求版本（编码字节与完整性摘要）
  tmp/<uuid>                发布前的临时文件
```

## 图片规则

接受 PNG/JPEG/WebP/GIF，校验真实格式并完整解码首帧。默认上限：20 MiB/张、20 张/批、200 MiB/批、6400 万像素、8192 最长边，通过构造参数 `imageLimits` 覆盖。
普通文件不设专属字节上限，按流存取，不提取或执行内容。
EXIF 方向校正后裁剪；越界报错；缩放不放大、保留透明度。动画原始字节保留，请求仅首帧并附说明。
`fullResolution` 不允许降低尺寸，编码后仍不满足硬限制则报错。处理并发默认 2，可配置 1–8。

缓存键覆盖原图、全部目标参数和算法版本。原图每次验证；缓存缺失/损坏可重建，不能靠缓存掩盖原图损坏。不设独立缓存 LRU、TTL 或容量淘汰。

## 清理和协调

原图从首次保存起无正式引用 30 天后可删除；曾引用对象首次可靠发现无引用时重新起算 30 天。
当前没有受控会话删除入口；外部删除会话以扫描发现时间起算，允许延后、不提前删除。
清理回调扫描全局完整日志，包含分叉副本、压缩前历史。扫描失败不删除。
SQLite `BEGIN IMMEDIATE` 使最终扫描/删除与消息提交互斥，操作登记保护保存/读取/编码。死进程登记下次回收；无法确认进程死亡时保守跳过，不用超时假设它已结束。
物理删除同时移除原图与派生版本。中途错误抛出，上次成功时间不推进；下一次可重试。

应用层 `create-attachment-runtime.ts` 启动时按持久时间补查，之后每 24 小时调用同一个回收入口。定时器 `unref`，关闭时停止调度。手动可调用 `collect(true)`。
应用退出前应结束全部操作并释放保护；仍有活跃操作时 `close()` 报错，避免关闭数据库后继续读写。

Node 22 的 `node:sqlite` 会显示实验性 API 警告。仅用于同一机器上的本地存储；不提供网络文件系统锁保证、跨机器共享、云后端或草稿租约。

## 模型请求

图片请求预算在 `llm-pi-ai/src/images.ts`，不是存储限制。适配器接受 `attachments.policy(model)` 覆盖。
默认应用预算：Anthropic API 115 万像素/1568 边；Google API 419 万像素/2048 边；其他 API 209 万像素/2048 边；单图 4 MiB、20 张，总字节 Google 12 MiB、其他 16 MiB。这些是本应用的发送预算，不声称等于厂商最大限额；自定义模型可覆盖。
必须有模型目录 `input: image` 声明；未知/文本模型拒绝图片。先准备再打开网络请求，错误不自动降级为纯文本。
超出总预算时仅卸载旧图片，以消息 occurrence key 加索引记录持久决定；当前运行轮次（包括 pending 输入和工具读图）受保护。卸载不释放正式引用。

专项测试：`node --test scripts/attachment-*.test.ts`（先 `npm run build`）。
